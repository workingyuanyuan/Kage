# AI 生成文件品質反模式 (AI Document Quality Anti-Patterns)

用於撰稿代理在交付前自查與品質驗收。以下整理 AI 生成專業文件時常見的品質反模式，分為六大核心類別與特殊場景，每條皆提供具體壞例與修正原則。

## 內容空洞 (Content Emptiness)

| 模式 | 壞例 | 改法 |
|---|---|---|
| 形容詞堆疊無數據 | EN: "Achieved significant growth across key metrics"<br>TW: 「在各項關鍵指標上皆取得顯著成長」 | 寫出具體數字："Revenue grew 34% YoY to $12M"／「營收較去年同期成長 34%，達 1,200 萬美元」。 |
| 開場白廢話填料 | EN: "In today's rapidly evolving landscape..."<br>TW: 「在當今瞬息萬變的市場環境中……」 | 直接刪除開場白，第一句就切入第一個實質論點與主張。 |
| 重述標題當段落 | 標題「營收成長」，內文寫「我們的營收成長相當顯著」 | 內文必須補充標題所未涵蓋的新資訊或具體因果分析。 |
| 模糊時間用語 | 「近期推出」、「在不久的將來」、「最近」 | 標明具體日期或季度：「於 2026 年第一季推出」。 |
| 同義詞包裝重複論點 | 連續三段用不同的換位詞重複表達「我們正在快速成長」 | 一個主張搭配一個證據，表達完畢即推進至下一個主題。 |

## 指標捏造 (Metric Fabrication)

| 模式 | 壞例 | 改法 |
|---|---|---|
| 虛假精確度的圓滑數字 | 來源寫「大約 1 萬人」，內文卻寫「剛好 10,000 名用戶」 | 配合來源精確度：「約 10,000 名用戶」。 |
| 假小數點精確度 | 未引用任何權威來源即寫出「市占率：23.7%」 | 標明數據來源，或四捨五入改寫為「約 24%」。 |
| 圖表與內文指標脫節 | 圖表顯示營收持平，內文卻寫「展現強勁成長動能」 | 內文論述必須與圖表呈現的趨勢與數據完全一致。 |
| 捏造無基準比較 | 「比替代方案快 3 倍」卻未列出任何測試數據 | 點明具體比較對象與測試基準方法；若無數據則刪除比較。 |
| 混用時間比較區間 | 將年增率 (YoY) 與季增率 (QoQ) 並列且未標示差異 | 為每個比較數據明確標示對應的時間視窗與基準。 |

## 結構模仿 (Structure Mimicry)

| 模式 | 壞例 | 改法 |
|---|---|---|
| 模板欄位充斥通用填料 | 特性或模組欄位填寫「溝通能力佳、團隊合作、解決問題」 | 寫明具體技術或領域應用場景；無具體內容即切除該欄位。 |
| 券商報告缺乏差異化觀點 | 「該公司營運穩健，具備良好的長遠成長優勢」 | 清楚指出市場目前的誤解，以及你的投資邏輯為何與市場共識不同。 |
| 單頁文件缺乏明確訴求 | 寫了三段背景脈絡，卻未說明「我們需要讀者採取什麼行動」 | 核心訴求 (Ask) 必須放在第一屏 (above the fold) 顯眼處，不得隱喻。 |
| 簡報標題僅作主題標籤 | 標題寫「第三季財報結果」或 "Q3 Results" | 採用「主張＋證據」句型：「第三季營收超越財測 12%」。 |

## 視覺與排版過度 (Visual & Layout Overuse)

| 模式 | 壞例 | 改法 |
|---|---|---|
| 24px 以下小字使用橘棕色 | 在正文或小於 24px 的文字套用 `--color-text-accent` 橘棕色 | 橘棕色對比度僅 3.98:1（漏光區 2.85:1），**小於 24px 文字禁止使用**。小字強調請用 `--color-text-on-dark` 加橘棕底線或符號。 |
| 強調色濫用與靜態背景化 | 畫面出現多個實心橘按鈕；或將 `--color-accent-hover` 鋪成靜態背景 | 單一畫面實心橘底 (`.btn-primary`) **至多 1 個**。`--color-accent-hover` 僅限 `:hover`/`:focus`，禁止作靜態背景。未選取結構件用中性色。 |
| 表面色鋪滿為全域背景 | 直接把深棕表面色 (`--color-surface-dark`) 當作 `background-color` 鋪滿整頁 | 深棕色僅能作為有邊界的卡片／面板表面。全域背景必須是由純黑基色、漏光與顆粒合成，遵循 luma 65 天花板。 |
| 淺色紙張面積超標 | 使用淺色紙張 (`.surf--paper`) 作為整頁背景，或面積超過畫面的 25% | 淺色紙張僅能做局部內容表面（引用區、表單、提示框），累計面積不得超過整頁 25%，正文應坐在深色底上。 |
| 平面化字級與假粗體 | 全部文字尺寸相近，並使用 `font-weight: bold` 合成假粗體 | 遵循字級階梯（`display` 64 → `h1` 44 → `h2` 30 → `body` 16px）。只用 400 與 600 字重，行內強調靠換色或底線，不靠加粗。 |
| 無襯線體主導視覺 | 使用無襯線體 (`--sans`) 渲染正文或大標題 | **標題與正文必須以襯線體 (`--serif`) 為主**。`--sans` 僅承擔導覽、日期、序號等結構輔助。中英須走同一條 `--serif` 鏈。 |
| 對稱式六六分欄 | 使用 6:6 對稱等寬分欄切割版面 | 禁用 6:6 對稱分割。採用 1.618:1（黃金比）、7:5 或 8:4 非對稱分欄，結合局部重疊與不對稱留白建立拼貼感。 |
| 超寬正文與圖文容器死綁 | 中文正文橫跨寬螢幕；或用卡片容器將圖片與一段文字強行綁在一起 | 中文正文行寬限制 `max-width: 38em`（28–42 字）。圖像承擔敘事、文字承擔結構，靠版面分欄與負空間嵌合，禁止卡片容器硬打包。 |
| 懸浮卡片與數位陰影 | 卡片加上大型模糊陰影（如 `box-shadow: 0 10px 30px rgba(0,0,0,0.5)`） | **不做懸浮卡片**。區域靠分欄、細線、深淺色差與負空間區隔。陰影上限 `0 1px 0`。禁用外發光、立體漸層、塑膠高光與霓虹邊框。 |
| 傳統攝影暗角打光 | 畫面採用中央亮、四角壓暗的傳統攝影暗角光暈 | **中央沉暗、邊緣漏光**。光源（暖色漏光 18–30°）錨定於畫面邊緣或外側，中央為最暗區域。禁用置中對稱圓形光暈。 |
| 削弱顆粒或混合錯誤 | 為了清晰而調低顆粒 `opacity`；或用 `overlay`/`soft-light` 疊加顆粒 | **顆粒不可削弱**，永遠 `opacity: 0.10`、`normal` 混合，全域覆蓋。可讀性靠局部暗部遮罩或紙張表面解決，不得全域調低。 |
| 具象照片裝飾母題 | 使用漂浮相框、撕裂紙邊、膠卷齒孔等照片圖檔作為版面裝飾 | 禁用具象照片圖檔裝飾。僅能使用純 CSS/SVG 生成的通用語彙：1px 幾何細線、塵點 (`--color-dust`)、刮痕、鏡像重影與邊緣微型字。 |
| 範圍描述型圖標題與圖說 | 圖表標題寫「各季度營收」，圖說寫「2023–2025 年營收數據」 | 標題與圖說必須傳達**判斷與洞察**：「第二季價格調整後，營收加速成長」／「營收在 Q3 轉正」。 |
| 圖示與 Emoji 充當清單標記 | 清單或段落標題開頭使用 Emoji (🚀/💡) 或裝飾圖示作項目符號 | 嚴禁用 Emoji 或圖示作項目符號。改用排版層級、數字 (`tabular-nums`) 或短線。圖示須為單色線稿，純裝飾加 `aria-hidden="true"`。 |
| 寬表格未設容器導致溢出 | 寬表格直接撐開版面，導致整個網頁出現水平滾動條 | 寬表格必須外包一層 `overflow-x: auto` 容器並設定 `min-width`，讓表格在自身容器內滾動。 |
| 狀態訊息僅靠顏色傳達 | 錯誤或警告訊息僅用一段紅字或黃字顯示 | 狀態訊息（錯誤、成功、警告）**禁止僅靠顏色傳達成敗**，必須同時包含 SVG 圖示與明確文字說明。低透明度底色須用 `color-mix`。 |
| 缺少結構訊號的互動狀態 | Hover/Active/Focus 狀態僅改變顏色，無結構變化 | 互動狀態除換色外必須有結構訊號：Hover 須有底線、位移；Active 須輕微內縮 `translateY(1px)`；Focus 須有清楚外框 (`outline`)。 |
| 簡報縱向滾動 Snap | 簡報投影片採用縱向 `scroll-snap-type: y mandatory` | 簡報為畫冊與唱片內頁的原型，**必須橫向 `scroll-snap-type: x mandatory`**。縱向 snap 屬於 scrollytelling 語彙。 |

## 來源缺口 (Source Gaps)

| 模式 | 壞例 | 改法 |
|---|---|---|
| 未經核實的版本號碼 | 「相容於 v4.2」（但官方最新版已更新至 v5.1） | 引用任何框架或工具版本號前，必須先與官方權威來源核實。 |
| 未標明日期的「最新」 | 「採用最新版的 Next.js 框架」 | 明確標註時間錨點：「採用 Next.js 15（截至 2026 年 4 月）」。 |
| 缺乏市場數據的競品比較 | 「市場上最領先的自動化解決方案」 | 引用具體市調機構報告與排名；若無數據則改用「市場上成熟的解決方案之一」。 |
| 未驗證的平台支援承諾 | 「支援所有主流作業系統與平台」 | 逐一列出經過實際測試與驗證的平台名稱（如 macOS, Windows, Linux）。 |

## 語氣污染 (Tone Pollution)

| 模式 | 壞例 | 改法 |
|---|---|---|
| 中文 AI 企業套話 | 「賦能企業數位轉型」、「打造一站式解決方案」 | 具體描述實際功能：「幫公司把紙本審核流程搬到線上」。 |
| 英文 AI 企業套話 | EN: "Leverage our platform to unlock synergies"<br>TW: 「發揮我們平台的優勢以釋放綜效」 | 簡明說明行為："Use the platform to share data between teams"／「使用該平台在團隊間共享資料」。 |
| 圖說同義重述流程圖 | 圖說寫：「六類來源 → 六道過濾 → 配比設計 → 訓練分片，四步串聯」 | 圖說應給出流程圖以外的價值判斷：「來源決定知識邊界，過濾決定乾淨程度，配比決定能力側重」。 |
| AI 贅詞與後設評論框架 | 「本質上是模型在做預測——這意味著……」、「值得注意的是」 | 刪除後設評論框架，直接講結論。破折號改用冒號或句號。自檢刪除：「本質是」、「這意味著」、「值得注意的是」。 |
| 圖說同義重述簡報標題 | 標題「ORM vs PRM 比較」，圖說寫「ORM 與 PRM 的比較」 | 圖說必須補充標題之外的資訊：取捨判斷標準、適用情境或下一步行動。 |

## 落地頁與元件細節 (Landing Page & Components)

| 模式 | 壞例 | 改法 |
|---|---|---|
| 貨幣符號縮小偏離基線 | `.price-currency { font-size: 0.5em; vertical-align: super }` 導致 `$` 浮在數字上方破壞基線 | 使用 `font-size: 0.74em; line-height: 1; transform: translateY(0.015em)` 保持 `$` 與數字共用基線。 |
| 多語言選單切斷下延筆畫 | `.lang-menu a { line-height: 1 }` 切斷 'g' / 'y' / 'p' 等字母底部 | 設定 `min-height: 32px; padding: 6px 10px; line-height: 1.35`，並加上透明 `::before` 橋接區防選單快閃消失。 |
| 中英數字混合基線跳動 | 中英混排處 `Mac/22/$19` 的數字因襯線體舊式數字 (oldstyle nums) 呈現高低不一 | 在所有顯示數字的節點加上 `font-variant-numeric: lining-nums tabular-nums`。 |
| 模板硬寫商業實體資料 | `<meta name="description" content="Acme 是一家 9 美元的清潔公司">` 寫死在模板中 | 保持 `{{PLACEHOLDER}}` 占位符，由用戶在文案階段填入。模板不得帶有特定真實產品資料。 |
| 多語言頁面與結構化資料未同步 | 主頁面更新了價格或安裝路徑，但其語系頁面或 JSON-LD / FAQ 仍顯示舊資料 | FAQ、JSON-LD、`llms.txt` 與多語系頁面視為單一事實集，修改時必須跨語系與檔案同步更新。 |
| 特色列交替排版造成空間空洞 | 左右交替的圖文列因文字填不滿欄寬，導致文字與圖片之間出現大面積空白穴 | 所有特色列維持統一對齊方向（使文字保持單一左緣）。僅在文字量充沛時做交替，勿在短清單做交替。 |
| 多語系頁面共用英文截圖 | 9 個語系頁面皆展示帶有英文選單的產品 UI 截圖 | 當產品 UI 已本地化時，截圖應按語系擷取與替換；本地化文案搭配英文截圖會破壞承諾。 |
| 社交分享圖格式與副檔名不符 | 將 PNG 圖檔直接重命名為 `.jpg` (RGBA 位元組以 `image/jpeg` 宣告) 導致社交卡片解析失敗 | 將 og:image 正確編碼為 1200x630 的標準 JPEG；使用 `file` 命令檢查實際位元組而非僅憑副檔名。 |
| 手貼動態計數器 | 頁面直接寫死「56.9k stars」，數週後即過時 | 於建置階段動態抓取數量，或在數字旁明確標註快照日期（如「截至 2026-04」）；無過期標示的手貼數字為無效資訊。 |

## 圖片與版位 (Image Slots)

| 模式 | 壞例 | 改法 |
|---|---|---|
| 先生成圖片再配版位 | 先生成 16:9 精美圖片，強行擠入 3:2 版面導致主視覺被裁切 | 先確定版位比例與空間，再依該比例進行裁切、留白或生成圖片。 |
| 真實產品截圖被 AI 重新繪製 | 產品 UI 截圖被 AI 重新繪製後，與實際發布的軟體介面不一致 | 保留真實產品截圖；需要美化時使用程式化內距或分割面板，不得重新繪製 UI。 |
| 混用不同比例截圖 | 同一圖庫面板中，三張截圖分別為直式、橫式與正方形 | 統一外框與 padding 規格，保持框內截圖內容完整。 |
| 缺產品截圖用意境圖填補 | 產品功能頁因缺乏真實截圖，而放入無關的抽象材質圖片 | 標示素材缺口或直接省略該面板，不得以無關意境圖充數。 |

## 簡報結構 (Slides)

| 模式 | 壞例 | 改法 |
|---|---|---|
| 標題串聯缺乏論證邏輯 | 僅閱讀各頁投影片標題時，得到的是一堆主題堆疊而非連貫論證 | 在設計版面之前，重新撰寫並排序投影片標題，確保單看標題即可構成完整敘事邏輯。 |
| 單頁堆疊多種證明型態 | 單張投影片同時包含圖表、UI 截圖、程式碼區塊與引言 | 挑選單一主要證明型態，其餘輔助材料拆分至相鄰投影片或附錄。 |
| 視覺指示洩漏至受眾文案 | 圖說寫著「21:9 超寬截圖，搭配沉靜背景」 | 將算圖提示與裁切說明留在版位地圖 (slot map) 中；受眾圖說只寫洞察與判斷。 |
